# Android feature parity

Status **Planned** means the existing client delivers the workflow and the RN destination and adapter are proposed. **Retain native** identifies Android entry points that must stay operational throughout migration. Tests in the right column are acceptance scenarios for that workflow. Only the development shell has an RN implementation in this milestone.

The names in the first column refer to sources in [briar-android](../briar-android/src/main/java/org/briarproject/briar/android). This matrix includes manifest activities, fragment-only screens, intent entry points and user-visible service behavior.

APK/API compatibility is checked independently of RN parity. Preserve the original client's supported OS range and include a current Android phone in transport and permission tests. Use the original client as the interoperability peer where a scenario requires one.
